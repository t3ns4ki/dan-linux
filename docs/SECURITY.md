# модель безопасности

## клиент

клиент — статические HTML/CSS/JS. секретных ключей в нём нет. SDK загружается локально после проверки публичной конфигурации. user-generated значения экранируются перед вставкой в HTML; терминальные команды/вывод рисуются через `textContent`. CSP ограничивает источники скриптов, соединений и объектов. SQL из пользовательских строк не собирается: запросы идут через параметризованные RPC SDK.

симулятор использует Map виртуальных файлов; в нём нет eval, Function, сетевого запроса, обращения к реальным файлам и запуска процессов. пути ограничены `/home/guest`, длина ввода/файлов/истории и объём файлов/пакетов ограничены. это учебное подмножество оболочки: grep ищет подстроку, а не все регулярные выражения; cc и пакетные менеджеры имитируются.

## PostgreSQL

RLS включён на всех пользовательских и каталожных таблицах. анонимам доступны только каталоги, открытые достижения и агрегированные результаты. скрытое достижение до обнаружения не выдаётся общим каталогом. владельцу доступны только его профиль, прогресс, достижения, голоса и история. email не хранится в public.profiles.

прямые insert/update/delete от anon/authenticated отозваны. SECURITY DEFINER RPC используют пустой search_path, проверяют подтверждённого auth.uid(), не принимают uid или XP из клиента. внутренние функции и ответы уроков закрыты в отдельной схеме. начисления определяются известными уроками и уникальными достижениями, повтор не даёт новые XP. максимальная сумма — 970 XP при текущих 26 уроках и 7 бонусах.

профиль имеет `is_private = true` на уровне ограничения. все профили в этом обновлении приватные; переключатель публичности не имитируется. предпочтения интерфейса и экспорт доступны владельцу.

голоса имеют первичный ключ `(user_id, category_id)`. функция проверяет тип кандидата и категории, блокирует строку профиля при изменениях и ограничивает аккаунт 8 изменениями в минуту. уроки ограничены 60 проверками в минуту. ошибочные ответы возвращают ошибку как данные, чтобы счётчик запросов не откатывался. история голоса видна владельцу, кабинет показывает последние 50 изменений. публичная функция возвращает только category_id, distro_id и vote_count.

## удаление

Edge Function проверяет фактического владельца токена через Supabase Auth и разрешённый origin. подтверждение, недавний вход и ограничения тела запроса уменьшают риск случайного удаления. service_role доступен только функции. auth.users удаляется административным API, все персональные строки каскадно удаляются БД. локальные гостевые записи остаются отдельными и удаляются владельцем в гостевом кабинете.

## границы

RLS не защищает от утечки service_role, вредоносных расширений браузера, захваченной почты или ошибочно изменённых администратором политик. публичные материалы и ответы доступны для изучения; XP — учебная мотивация, а не доказательство сдачи экзамена. один аккаунт — один активный голос, но создание нескольких аккаунтов человеком технически возможно. CAPTCHA и внешняя антифрод-система не подключены. отдельного публичного профиля, комментариев, загрузки аватаров и произвольного HTML нет.

автоматические тесты проверяют реальную PostgreSQL-логику локально. настройки твоего Supabase, SMTP, OAuth, доступы Dashboard и опубликованную Edge Function нужно проверить отдельно после подключения.


## Share и граница RPC

подробная модель прав, Storage и лимитов описана в [SHARE.md](SHARE.md). миграция `dan_linux_rpc_boundary` переносит привилегированные реализации в неэкспонируемую `dan_private`; в public остаются SECURITY INVOKER обёртки с явными ACL. private-таблицы закрыты RLS. тесты выполняют исходную схему и обе миграции в PostgreSQL. клиент не может менять роли/XP или одобрять свою запись обходом кнопок. origin-проверка Edge Function дополняет проверку JWT и не заменяет её.

настройки языка переводят только авторские UI-тексты через textContent и атрибуты. пользовательский контент явно исключён. geo-запрос идёт country.is с IP браузера, без cookies/referrer; сохраняются только ISO-код и время, в Supabase эти данные не отправляются.
