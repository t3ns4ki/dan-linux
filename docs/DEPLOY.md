# публикация обновления

## сохранить исходный сайт

обновление подготовлено поверх коммита `ad3d884240ca3c08514ba65f605ab91e284b1537` репозитория `t3ns4ki/dan-linux`. если после него ты менял сайт, сначала сохрани свои изменения и объедини их. не заменяй новые файлы вслепую старым архивом.

автор выбрал GPL-3.0-or-later. сохраняй LICENSE, NOTICE и лицензионные уведомления шрифтов и SDK при публикации.

## способ 1: через GitHub в браузере

1. распакуй `dan-linux-2.0-source.zip`.
2. настрой Supabase по `docs/SUPABASE.md` или оставь сервис отключённым для предварительного гостевого запуска.
3. открой свой **существующий** репозиторий `t3ns4ki/dan-linux`, создай ветку `dan-linux-2.0`.
4. Add file → Upload files: перетащи содержимое архива с сохранением подпапок. `index.html` должен лежать в корне репозитория, а не в дополнительной папке `dan-linux-2.0/`.
5. добавь также скачанный архив исходников **под именем `dan-linux-2.0-source.zip` в корень репозитория**, чтобы кнопка «скачать исходный код» в подвале работала. архив не содержит сам себя. он также генерируется командой упаковки ниже.
6. создай pull request, проверь изменения и объедини в основную ветку. не загружай `node_modules`, `.git`, `.env` и приватные ключи.
7. Settings → Pages → Build and deployment: **Deploy from a branch**, твоя основная ветка, каталог **`/ (root)`**, Save. `.nojekyll` сохранён. если уже используется собственный Actions workflow, сохраняй его и публикуй корень статического сайта.
8. дождись успешного Pages deployment в Actions. адрес: **`https://t3ns4ki.github.io/dan-linux/`**.

если не используешь купленный и настроенный домен, поле Custom domain должно быть пустым. не добавляй CNAME к чужому или незарегистрированному домену.

## способ 2: через Git

в своём актуальном клоне сохрани отдельную ветку, затем скопируй туда файлы обновления, сохранив свой LICENSE и более свежие изменения:

```bash
git switch -c dan-linux-2.0
git status
npm ci
npm run build
npm run check
npm test
python3 scripts/package-source.py
cp build/dan-linux-2.0-source.zip dan-linux-2.0-source.zip
git add .
git diff --cached --stat
git commit -m "Add Dan Linux 2.0 Academy, command generator and Supabase community"
git push -u origin dan-linux-2.0
```

создай PR в GitHub и объедини после проверки. можно вместо копирования применить приложенный `.patch`: сначала `git apply --check ПУТЬ_К_PATCH`, затем `git apply ПУТЬ_К_PATCH`; это применимо к совместимой исходной версии. при конфликте остановись и объедини изменения вручную.

команда упаковки не добавляет секреты и служебные каталоги. она включает публичный `config.js`: перед запуском убедись, что в нём только Publishable Key. после изменения файлов пересобери ZIP — иначе кнопка скачивания будет отдавать старую версию.

## после публикации

- проверь навигацию, старый подбор дистрибутива, поиск, тему, Academy и терминал на телефоне и компьютере.
- при подключённом Supabase проверь сценарии из `SUPABASE.md`. публичный `config.js` не заменяет запуск SQL и Edge Function.
- все ссылки на ассеты относительные, поэтому подпапка GitHub Pages поддерживается. Auth возвращается на тот же корневой адрес страницы без отдельного серверного маршрута.
- `supabase/` — исходники серверных настроек: GitHub Pages не выполняет SQL и Deno. их нужно применить в Supabase отдельно.
- для отката верни предыдущий commit через `git revert` и повторную публикацию. база автоматически не откатывается; перед изменениями рабочей БД сохраняй резервную копию.
