# DanLinux Share

главная страница содержит кнопку DanLinux Share. на GitHub Pages раздел открывается по адресу `https://t3ns4ki.github.io/dan-linux/share/`. вложенный `index.html` использует `<base href="../">`: общие ассеты и возврат Auth направлены в корень сайта.

## правила модерации

| автор | первоначальный статус | кто проверяет |
| --- | --- | --- |
| обычный подтверждённый пользователь | pending | owner или admin |
| admin | pending | только owner |
| owner | approved после завершения изображения | публикация сразу |

те же правила действуют для комментариев. роль берётся из закрытой таблицы БД по Auth UUID. никнейм не выдаёт прав и не резервируется. первый зарегистрировавшийся не становится владельцем.

кнопка «ждущие на проверку» видна модераторам. admin получает только разрешённые ему записи; owner — всю очередь. одобрение и отклонение проверяются на сервере, включая версию записи. причина отклонения видна автору. опубликованную запись можно снять с публикации.

если admin лишился роли, его прежние сообщения всё ещё требуют проверки владельцем. если пользователь получил admin после отправки, проверка его сообщений также ограничивается владельцем. скрыть кнопку в браузере недостаточно: каждое действие контролирует БД.

## назначение первого owner

1. зарегистрируй **свой** аккаунт на сайте, подтверди почту и войди.
2. профиль → «приватность и сеанс» → **ID твоего аккаунта** → «копировать ID». это UUID, а не пароль и не ключ API.
3. сверяй UUID с Authentication → Users в **своём** Supabase-проекте. не ориентируйся только на ник или порядок регистрации.
4. в доверенном SQL Editor выполни следующий запрос, подставив проверенный UUID вместо текста в угловых скобках:

```sql
insert into dan_private.share_roles(user_id, role)
values ('<UUID твоего подтверждённого аккаунта>'::uuid, 'owner');
```

этот пример не исполняется без настоящего UUID. единственный owner обеспечивается уникальным индексом. не выдавай роль случайному аккаунту.

после обновления страницы появятся owner и управление админами. в «админы» найди пользователя по точному никнейму, сверь ID и подтверди назначение. одинаковые никнеймы допустимы, поэтому они не являются доказательством личности.

для восстановления доступа владельцем используется доверенный SQL Editor, а не скрытая клиентская кнопка. смену owner выполняй только после проверки нового аккаунта.

## изображения и приватность

- один PNG/JPEG/WebP до 8 МБ; браузер преобразует в WebP до 1600 px и 4 МиБ, убирая исходные метаданные.
- нельзя загружать SVG или HTML. подписи, названия и комментарии отображаются только текстом; HTML не исполняется.
- bucket `dan-share` приватный. временная подписанная ссылка живёт 60 секунд и создаётся после проверки доступа. уже выданная ссылка может действовать до истечения срока даже после снятия публикации.
- неизменяемый путь изображения связан с черновиком записи. нет Storage UPDATE-политики, поэтому автор не может заменить уже проверенную картинку под тем же адресом.
- до одобрения файл доступен автору и разрешённому проверяющему. после одобрения — всем читателям.
- email, Auth UUID автора, приватный профиль и учебный прогресс не выдаются публичной лентой. публичны никнейм, выбранный аватар, роль, текст и время записи.
- пользователи могут отозвать свои записи. удаление аккаунта сначала блокирует новую загрузку и удаляет его файлы через Storage API, затем удаляет Auth-пользователя и связанные строки каскадно.
- отозванные записи и черновики сохраняются до удаления аккаунта; автоматическая очистка заброшенных файлов не настроена.

## ограничения

RPC ограничивают публикации: 2 записи/минуту, 20/день и не более 8 ожидающих; комментарии — 5/минуту, 100/день и не более 15 ожидающих. повторное голосование ограничено уникальным аккаунтом. подтверждение почты обязательно. это защита от простых повторов, а не доказательство того, что один человек не создаст несколько аккаунтов.

автоматический ИИ-модератор не подключён. сайт не обращается к ChatGPT для проверки публикаций. owner/admin выполняют проверку вручную. для публичного сообщества дополнительно настрой SMTP, Auth rate limits и подходящую защиту регистрации в Dashboard.
