# настройка Supabase

## текущее состояние — 25 ноября 2026

реальный проект **dan-linux** (`xrytmooypzycvrzuatdg`) уже подключён. первоначальная схема, миграции `dan_linux_share` и `dan_linux_rpc_boundary` применены. bucket приватный. `delete-account` развёрнута, версия 1 ACTIVE. Security Advisor после миграций не выдал замечаний. повторно применять эти файлы в текущей базе **не нужно**.

email signup включён, подтверждение обязательно; Google/GitHub выключены. SMTP и реальную доставку писем агент не настраивал. подтверждённых аккаунтов на момент проверки нет, owner не назначен. [инструкция назначения владельца](SHARE.md) использует проверенный Auth UUID, не никнейм.

тебе остаётся проверить Auth Site URL / Redirect URLs, настроить SMTP для друзей и зарегистрировать свой аккаунт. дальнейшие разделы описывают полную установку **для отдельного нового проекта**, а не повторный запуск в существующем.

## 1. создать отдельный проект

1. войди в [Supabase Dashboard](https://supabase.com/dashboard) и создай проект. выбери регион, задай надёжный пароль БД и сохрани его приватно.
2. дождись готовности проекта. в SQL Editor создай новый запрос.
3. вставь **весь** `supabase/schema.sql` и выполни. затем последовательно выполни `supabase/migrations/20261125133404_dan_linux_share.sql` и `supabase/migrations/20261125135054_dan_linux_rpc_boundary.sql`. порядок важен. он создаёт каталоги и защищённые таблицы, но не добавляет голоса.
4. файл рассчитан на **новый проект**. повторный запуск завершится ошибкой существующих объектов; транзакция не оставит частично созданную схему. не удаляй рабочие таблицы ради повторного запуска.

создаются `profiles`, `academy_progress`, `achievements`, `user_achievements`, `voting_categories`, `distros`, `votes`, а также `academy_lessons`, `vote_history` и закрытая схема `dan_private`. RLS уже включён. доступ к записи идёт через проверяющие RPC, а не прямой insert из браузера.

## 2. настроить Auth и письма

1. Authentication → Sign In / Providers: включи Email и **Confirm email**. не отключай подтверждение ради теста — RPC всё равно требуют подтверждённую почту.
2. в URL Configuration задай Site URL **`https://t3ns4ki.github.io/dan-linux/`**.
3. добавь этот же полный адрес в Redirect URLs. для локальной разработки отдельно добавь `http://localhost:8000/`. для другого домена добавь точный адрес этого сайта. для проверки приватного предпросмотра можно добавить `https://dan-open-source-linux.largedace4.chatgpt.site/`; он нужен только для возврата писем/OAuth из предпросмотра. если вход нужен только на GitHub Pages, добавлять его не обязательно. `/share/` использует callback на корень сайта. завершающий `/` важен.
4. укажи минимальную длину пароля не меньше 12 символов и подходящие настройки Auth Rate Limits.
5. для писем посетителям настрой свой SMTP-провайдер в Authentication → Email / SMTP. ограничения встроенной почты и доступность бесплатных тарифов проверяй в Dashboard: встроенная отправка не предназначена для полноценного публичного сервиса.
6. оставь стандартные шаблоны подтверждения и восстановления со ссылкой `{{ .ConfirmationURL }}`. здесь используется PKCE; письмо открывай в том же браузере, где была начата регистрация или восстановление. при выключенном «запомнить вход» — в той же вкладке. иначе verifier может отсутствовать, и запрос нужно повторить.

пароли обрабатывает Supabase Auth; сайт их не записывает. пункт «запомнить вход» выбирает localStorage или sessionStorage для сессии. сама сессия необходима для дальнейших защищённых запросов.

## 3. заполнить публичную конфигурацию

в настройках проекта найди **Project URL** и API Keys → **Publishable key**. в `config.js` вставь именно свои значения:

```js
window.DAN_CONFIG = Object.freeze({
  supabaseUrl: '', // вставь свой Project URL вида https://…supabase.co
  supabasePublishableKey: '', // вставь только sb_publishable_…
  oauthProviders: [],
  deleteAccountFunction: 'delete-account',
  votingPollSeconds: 30
});
```

пустые строки выше — поля для твоих реальных значений, а не готовые реквизиты. legacy anon JWT здесь намеренно не используется. Publishable Key виден посетителям: защиту персональных данных обеспечивают Auth и RLS. SDK загрузится после правильной конфигурации. при изменении ключа полностью перезагрузи страницу.

## 4. GitHub и Google — по желанию

основной вход по почте не требует OAuth.

### GitHub

1. GitHub → Settings → Developer settings → OAuth Apps → New OAuth App.
2. Homepage URL — адрес сайта. **Authorization callback URL скопируй из Supabase → Authentication → Providers → GitHub**; это адрес Supabase `/auth/v1/callback`, а не страница GitHub Pages.
3. Client ID и **Client Secret** сохрани только в настройках провайдера GitHub в Supabase. включи провайдер.
4. добавь `'github'` в `oauthProviders` в `config.js`.

### Google

1. в Google Cloud Console создай OAuth client для Web application и настрой consent screen.
2. Authorized JavaScript origins — `https://t3ns4ki.github.io`; Authorized redirect URI — callback из Supabase → Providers → Google.
3. Client ID/Secret сохрани только в Supabase. включи провайдер. в тестовом режиме Google разреши нужных тестовых пользователей; перед публичным запуском настрой аудиторию приложения.
4. добавь `'google'` в `oauthProviders`.

пока соответствующая строка не добавлена, кнопка провайдера не появляется. добавляй её после завершения настройки.

## 5. развернуть удаление аккаунта

в текущем проекте эта функция уже развёрнута. инструкции ниже нужны при переносе на другой проект. без этой функции вход и база работают, но удаление из кабинета не будет выполнено. его нельзя заменять клиентским service_role key.

установи официальный [Supabase CLI](https://supabase.com/docs/guides/cli/getting-started), затем из корня проекта:

```bash
supabase login
supabase link
supabase secrets set ALLOWED_ORIGINS=https://t3ns4ki.github.io
supabase functions deploy delete-account
```

`supabase link` предложит выбрать проект; убедись, что это нужная база. `ALLOWED_ORIGINS` — origin без `/dan-linux/`, без завершающего слеша. если позже появится свой домен, перечисли разрешённые origins через запятую. localhost добавляй только для необходимого тестирования.

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` предоставляются серверной средой Supabase. код читает их **только внутри Edge Function**. не копируй их в Git, `config.js`, README, клиент или аргументы публикации сайта.

в `supabase/config.toml` оставлен `verify_jwt = true`, потому что запрос поступает с JWT вошедшего пользователя. функция дополнительно проверяет токен через `auth.getUser(token)`, подтверждённую почту, origin, POST, намерение удаления и вход в последние 15 минут. она удаляет только владельца проверенного JWT; присланный `user_id` игнорируется. связанные строки удаляются внешними ключами `ON DELETE CASCADE`.

если удаление требует нового входа, выйди и войди снова. обновление токена само по себе не считается новым входом. восстановленный сеанс по почте не заменяет повторную проверку входом.

## 6. проверка перед приглашением друзей

создай два **своих тестовых** аккаунта с разными адресами и подтверди оба. проверь:

1. регистрацию, письмо, вход/выход, восстановление и обновление страницы; каждый включённый OAuth отдельно.
2. урок, XP, повторное выполнение без второго начисления и синхронизацию на другом устройстве.
3. перенос гостевого прогресса отдельной кнопкой в профиле.
4. один голос → другой дистрибутив → отзыв; другая вкладка должна увидеть изменение после «обновить» или в пределах интервала опроса.
5. второй аккаунт не видит приватный профиль, уроки и историю первого. никнеймы и почта не выдаются публичным рейтингом.
6. удаление только специально созданного тестового аккаунта: профиль, уроки, достижения, голоса и история исчезают.
7. DevTools → Console/Network: нет ошибок RPC, CORS, SMTP и OAuth. в ответах публичного `voting_results` нет user_id и email.

## ограничения защиты от накруток

уникальный ключ в БД запрещает несколько активных голосов **одного аккаунта** в одной категории. проверка почты и лимит 8 изменений голоса в минуту затрудняют простую автоматизацию, но не доказывают правило «один человек — один аккаунт».

настрой Auth rate limits и SMTP; при росте аудитории можно подключить CAPTCHA, но для неё понадобится отдельная конфигурация клиента и ключи провайдера. в этом обновлении CAPTCHA не заявлена как включённая. XP конечен и проверяется сервером, но учебные ответы не являются экзаменом с контролем личности.
